players play), P = predictive (out-of-sample improvement), C = causal / counterfactual. **Status**: supported,

ratings fairly, but it is **not** a pregame forecast. Only the live test (court-live, from 2026-11-27) is pregame.

## Material issues (code-level)

- **I1. Realized rosters inside "pregame" quantities.** `ms_fit.py:84` (`gl[gl['min'] > 0]`) drops players who sat, so `Pregame.teams` covers only players who actually played. Used by `calibrate_live.py:51,65` to fit the frozen live calibration, and by the older "pregame" benchmark. Separately, every block test (`ms_bench`, `ms_duncan2`, `ms_defw`, `trk_bench`) is given-lineup by design and should be labelled that way.
- **I2. Movers selected with future playing time.** `ms_shrink_d2.py:54`, `ms_movers.py:72`, `ms_movers_trk.py:102`, `trk_bench.py:206-209` define movers by possessions played for a new team *after* the cutoff, then apply the pull only to them. Pregame, a mover is known from transactions (or DARKO's `tm_id` on the cutoff date), and some movers never play.
- **I3. Post-cutoff information in learned tracking representations.** BOWEN is cross-fitted by random game folds across both seasons (`world_model.py:172-176`), so predictions for pre-deadline games come from a network trained partly on post-deadline games. The BORIS GMM is fitted on pooled possessions from both seasons (`archetype_mix.py:48`). Tracking xFG is in-sample before 2026-04-01 (`shot_model.py:14`). This affects D5, D11 and the trk_bench C/D/H arms.
- **I4. Repeated tuning on evaluation data.** The 6,057-game blocks have been reused for many design choices (luck strength, priors, λ grid, shrinkage), so D1-D3 are selection-affected; the live test is the clean verdict. pop_synergy's λ_s grid was extended after a first look at test-period results (mild; S1 survives on the original grid).
- **I5. Uncertainty narrower than the claims.** Game-level bootstraps ignore block/time correlation and prior selection. ms_movers_trk has two events but resamples games. trk_bench reports about 20 unadjusted CIs.
- **I6. DARKO point-in-time status unverified.** Stability over 4 days does not show DARKO's history equals what was published on each historical date.

## Prioritized corrective plan (smallest experiments)

1. **Chronological movers (I2, I3; affects D4, D5).** Define movers from team at cutoff: the last game for team A before the cutoff and the first game for team B on or after it, from the box-score team per game, regardless of later minutes (transaction-time proxy). Report the "≥ MIN_POST later possessions" filter as a separate, labelled eligibility stratum. Rerun `ms_shrink_d2.py` and `ms_movers_trk.py` with BOWEN team schemes taken only from a network trained on games before each cutoff (two retrains: < 2026-02-05, < 2026-10-20, ~1 h GPU each), and BORIS GMMs refit on pre-cutoff possessions.
2. **Calibration without realized rosters (I1; affects L1).** Refit both calibrations with `Pregame` keeping every player with prior minutes on the roster at game time (drop the `min > 0` filter; weight by previous-10 minutes), compare slopes and reliability on 2025-26. Report only; the frozen live calibration stays (amendment only if pre-declared).
3. **Relabel given-lineup results (I1).** D1-D3, D9, D11, D12, S1: label "given realized lineups". No rerun needed.
4. **Block bootstrap (I5).** Recompute D1-D3 and S1 CIs resampling 30-day blocks instead of games (read-only on saved npz/json).
5. **BOWEN causal encoder (I3, W1).** Ablation: scheme encoder restricted to frames ≤ t (forward GRU, masked). Compare error 5.59 ft and execution reliability.
6. **BOWEN scheme-follows-team, leave-self-out (W3).** Recompute the team mean excluding the player; report the new r. Cheap, read-only.
7. **DARKO point-in-time spot check (I6).** Compare a handful of dates against archived snapshots (e.g. web archive copies of darko.app) if any exist. If none exist, mark D1-D4 "DARKO PIT unverified".
8. **Save what was only printed:** pair_validate, darko_hindsight, ms_duncan2 CIs → json.
